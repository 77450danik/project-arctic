# M3 — GPU: робочі нотатки

Як відеокарта отримує драйвер, як кадр програми доходить до монітора і коли
вмикається змінна частота оновлення (VRR). Документ робочий: оновлюється, поки
йде M3.

## Драйвер для будь-якої карти

Як у Windows 11 або в сучасному дистрибутиві: жодного вибору вручну.

| Карта | Ядро | OpenGL / Vulkan |
|---|---|---|
| AMD GCN 1.0 і новіші (HD 7000 → RX 9000) | `amdgpu` | radeonsi / radv |
| AMD до GCN (HD 2000–6000) | `radeon` | r600 / — |
| Intel Gen 7–12 | `i915` | iris, crocus / anv, hasvk |
| Intel Xe2 і новіші (Lunar Lake, Battlemage) | `xe` | iris / anv |
| NVIDIA Turing і новіші (GTX 16, RTX 20 → RTX 50) | `nvidia` (відкриті модулі) | NVIDIA |
| NVIDIA Maxwell, Pascal, Volta (GTX 750 → GTX 10, Titan V) | `nvidia` (закриті модулі 580) | NVIDIA |
| NVIDIA Kepler і старші (GTX 600/700) | `nouveau` | nouveau / NVK |
| Немає драйвера / QEMU / `nomodeset` | `simpledrm` | llvmpipe / lavapipe |

Як це влаштовано:

- **Модулі ядра** — усі DRM-драйвери з конфігу Arch, модулями. `udevd` вантажить
  їх за PCI-ідентифікатором.
- **NVIDIA.** Гілка 580 — остання, що підтримує Pascal і старші. З її
  `.run` (`kernel/NVIDIA_VERSION`) `ci/build-kernel.sh` збирає два набори
  модулів, підписаних ключем ядра: відкриті (Turing і новіші) — у дерево
  модулів, закриті (Maxwell, Pascal, Volta) — у `/usr/lib/arctic/nvidia-legacy`.
  Userspace ставить `ci/install-nvidia-userspace.py` з того самого `.run` за
  його маніфестом (Arch пакує лише найновішу гілку). Щоб оновити NVIDIA:
  змінити `kernel/NVIDIA_VERSION` і перезібрати ядро й образ.
- **Хто бере карту.** Відкритий `nvidia` вантажиться за аліасом і сам
  відмовляється від карт без GSP (до Turing). `nouveau` для автозавантаження
  заблокований (`arctic-gpu.conf`). `arctic-gpu` (`host/init/arctic-gpu.c`),
  якого udev запускає для кожного відеоадаптера, дивиться, чи прив'язався
  драйвер: якщо ні, а карта Maxwell…Volta (0x1340–0x1DFF), — вивантажує
  відкриті модулі й вантажить закриті (`nvidia`, `nvidia-modeset`,
  `nvidia-drm modeset=1 fbdev=1`, `nvidia-uvm`); інакше — `nouveau`; якщо це
  відкритий `nvidia` — довантажує `nvidia_drm` (у нього немає аліасу). Що
  вибрано, видно в `kernel.log`: `arctic-gpu: 10de:1c8d: NVIDIA's proprietary driver`.
  Навіщо: `nouveau` не піднімає частоти Pascal (підписана прошивка), і GTX
  1050 працював на стартових — WebGPU у Chrome давав 4–5 кадрів/с.
- **Старі Radeon.** GCN 1.0/1.1 за замовчуванням бере `radeon`, без Vulkan.
  `/etc/modprobe.d/arctic-gpu.conf` віддає їх `amdgpu`.
- **Прошивки:** `linux-firmware-{amdgpu,radeon,intel,nvidia}`; GSP для
  відкритих модулів NVIDIA — з `.run` (`/usr/lib/firmware/nvidia/<версія>`).
- **Userspace:** `mesa`, `vulkan-radeon`, `vulkan-intel`, `vulkan-nouveau`,
  `vulkan-swrast` і NVIDIA. Завантажувач Vulkan бачить усі ICD і бере ті, що
  знаходять свою карту.

**Який екран бере dwm.** Картку з підключеним монітором; якщо таких кілька —
ту, на якій прошивка показала картинку (`boot_vga`), як Windows стартує на
основному адаптері. Коли драйвер GPU завантажився, `simpledrm` зникає сам
(ядро забирає в нього кадровий буфер).

**Драйвер, що прийшов пізніше.** Зазвичай драйвер GPU вже прив'язаний, коли
стартує dwm (`udevadm settle` чекає до 60 с). Якщо ні (повільна ініціалізація
GSP, прошивка), dwm стартує на `simpledrm`, а коли той зникає — сам
переходить на нову картку: `dwm: /dev/dri/card0 went away`, потім
`dwm: display /dev/dri/card1 (…)` і рідний режим монітора. Так Windows
переходить з «Базового адаптера дисплея» на драйвер карти без
перезавантаження. Поки картки нема, клієнти бачать старі монітори («паркуються»),
а приберуться вони через секунду після появи нових — для Windows-сторони це
звичайне гаряче підключення 1 → 2 → 1, без миті «жодного монітора».

Перевірка в QEMU: `vm-shell.py --append "modprobe.blacklist=bochs vga=0x318"`,
потім у консолі `/usr/bin/modprobe bochs` (саме повний шлях: `modprobe` у
busybox не читає стиснуті модулі).

**Відкрите:** екран перемикається, але робочий стіл Windows після заміни
*єдиного* монітора лишається старого розміру (win32u бачить `2 monitors,
desktop 1280x800`, а після прибирання старого — знову 1024x768 на
`\\.\DISPLAY1`). Назва адаптера у вже запущених програмах теж лишається
старою.

**Патч `0033` (winewayland).** До нього зміни моніторів узагалі не доходили
до win32u: драйвер оновлює пристрої лише в процесі робочого столу і
визначав це з потоку читання Wayland, а в csrss цей потік належить іншому
робочому столу (успадкованому від `start.exe`). Тепер драйвер запам'ятовує
вікно робочого столу, коли його створює власний процес. Це стосується й
гарячого підключення моніторів на залізі (M2).

## Шлях кадру

```
програма ── GDI ──────── wl_shm ──► dwm: копія при commit ─┐
         └─ Vulkan/GL ── dmabuf ──► dwm: буфер тримається ─┤
                                                          ▼
          вікно на весь монітор з GPU-буфером?  ── так ──► пряме сканування:
                     │                                      flip на буфер гри,
                     ні                                     курсор — апаратна площина,
                     ▼                                      VRR увімкнено
          композиція на GPU (OpenGL ES) у буфер GBM-поверхні монітора ──► page flip
          (без EGL: композиція на CPU у тіньовий кадр → dumb-буфер ──► page flip)
```

- **Композиція на GPU** (`gl.c`, з 2026-09-29). Кожен монітор має GBM-поверхню
  на картці dwm, кадр малюється OpenGL ES і її буфер іде у flip. dmabuf-вікна
  (Vulkan, DXVK) — текстури просто з їхніх буферів (EGLImage), без копії; GDI-вікна
  завантажуються текстурою, коли змінились. Без GPU (QEMU, `nomodeset`) той самий
  шлях малює llvmpipe у dumb-буфери (`dwm: composing on the GPU: llvmpipe`).
  Лише якщо EGL не стартує, композиція йде на CPU, як раніше (`composing on the
  CPU`); примусово — `ARCTIC_DWM_CPU=1`.
- **Ефекти Windows 11** (лише на GPU-шляху): кути вікон з рамкою заокруглені на
  4 px (половина радіуса Windows 11; максимізованих і повноекранних — ні,
  `DWMWA_WINDOW_CORNER_PREFERENCE` шанується); акрил за вікнами, що його просять
  (`SetWindowCompositionAttribute` — панель задач, Alt+Tab, мініатюри): розмиття
  dual Kawase, насиченість, тонування, зерно; анімації відкриття/закриття
  (масштаб 0,94 + прозорість), згортання в кнопку на панелі й розгортання з неї,
  максимізації, появи меню й flyout-ів, «виїзд» меню «Пуск» — за кривими
  Windows 11. Вікно, що зникло, доанімовується з останнього кадру (знімок перед
  тим, як поверхня отримала інший розмір або зникла). `+dwm` у
  `arctic.winedebug=` показує кожну анімацію.
- **DWM-мініатюри** (`DwmRegisterThumbnail`) малює dwm: живий вміст вікна або,
  для згорнутого, його останній кадр. Атрибути вікон і мініатюри dwmapi пише у
  спільну секцію `Global\__arctic_dwm` (`wine/arctic_dwm.h`), dwm її читає.
- **GDI над акрилом.** Вікно з акрилом малює чорний фон; піксель без власної
  альфи dwm бере за яскравістю (чорне — прозоре, білий текст — білий), піксель з
  альфою (значки, `AlphaBlend`) — як є.

- **Page flip замість малювання у видимий буфер.** На кожен монітор — два
  dumb-буфери: один на екрані, у другий малюється наступний кадр, потім flip.
  Розриву кадру більше немає. Кадр робиться, коли щось змінилося **і** монітор
  показав попередній (подія завершення flip), тож кожен монітор іде у своєму
  темпі. Драйвер, що не вміє flip, отримує кадри як раніше (малювання у
  видимий буфер + `DIRTYFB`).
- **Драйвери без справжнього vblank** (`simpledrm`, віртуальні карти QEMU)
  завершують flip одразу. dwm це помічає (`flips without a vertical blank`) і
  тримає темп таймером на частоті режиму.
- **Atomic KMS** вмикається, коли драйвер його має (усі сучасні, крім
  `radeon`). Зміна режиму лишилась старим `SETCRTC` — перевіреним у M2; flip,
  пряме сканування і VRR ідуть atomic-комітами.
- **dmabuf** (`zwp_linux_dmabuf_v1` v4, `dmabuf.c`). Поки пропонуються лише
  лінійні XRGB8888/ARGB8888: їх уміє і прочитати CPU-композиція, і показати
  монітор. Головний пристрій у feedback — картка dwm, тож на ноутбуці гра на
  дискретній карті сама копіює кадр на вбудовану (PRIME).
- **Кадр-колбеки** (`wl_surface.frame`) ідуть, коли flip завершився; так
  FIFO у Vulkan тримає темп монітора, а з VRR — темп гри.

## VRR

Як у Windows 11 з увімкненим FreeSync/G-SYNC: на робочому столі частота
фіксована, а коли вікно з GPU-буфером закриває весь монітор (гра, відео на
весь екран), dwm вмикає `VRR_ENABLED` на CRTC. Монітор тоді оновлюється тоді,
коли гра віддала кадр.

- Монітор має VRR, якщо конектор каже `vrr_capable` (драйвер перевірив EDID і
  з'єднання). У `dwm.log`: `dwm: monitor on DP-1, …, variable refresh`.
- Увімкнення/вимкнення: `dwm: DP-1 variable refresh on` / `off`.
- Якщо драйвер не дає перемкнути VRR без повного modeset (екран блимнув би) —
  dwm не перемикає і пише `cannot switch variable refresh without a modeset`.
- **Для користувача — у Панелі керування.** «Екран» → «Параметри»: під
  частотою оновлення з'являється прапорець «Змінна частота оновлення», але
  лише для монітора, який разом із відеокартою її підтримує (як перемикач
  FreeSync у панелі AMD). За замовчуванням увімкнено; «Застосувати» діє
  одразу, без перезавантаження. Вибір — окремо для кожного монітора.
- **Де це лежить:** `HKLM\SYSTEM\CurrentControlSet\Control\GraphicsDrivers\MonitorDataStore\<PnP-ID>`
  (PnP-ID з EDID, напр. `AUS27B1`, як win32u називає пристрій монітора):
  `VariableRefreshCapable` пише dwm, `VariableRefresh` — панель (патч ReactOS
  `0016`). dwm стежить за ключем.
- Додатково діє загальне налаштування DirectX Windows 11
  (`HKCU\Software\Microsoft\DirectX\UserGpuPreferences`,
  `DirectXUserGlobalSettings`, `VRROptimizeEnable=0` вимикає для всіх).

## Пряме сканування

Умови, щоб монітор показував буфер гри без композиції (у Windows це
Independent Flip):

- найвище видиме вікно на моніторі точно збігається з ним;
- його верхня поверхня — dmabuf, що покриває все вікно без обрізання
  viewport;
- картка приймає буфер як framebuffer і atomic `TEST_ONLY` проходить (перевірка
  раз на буфер і CRTC);
- є апаратний курсор (`DRM_IOCTL_MODE_CURSOR`): стрілку не можна намалювати
  в буфер гри.

Якщо щось не так, вікно просто композиться — з VRR, якщо воно на весь монітор.

## Курсор

Видимість курсора тепер береться з wineserver (патч `0032`): якщо потік вікна
під курсором сховав його (`ShowCursor(FALSE)`, `SetCursor(NULL)`), dwm його не
малює — ні в композиції, ні на апаратній площині. Форма поки одна — стрілка.

## Перевірка

- Користувач: «Екран» → «Параметри» — прапорець «Змінна частота оновлення»
  видно лише на моніторі з FreeSync / G-SYNC Compatible. Гра на весь екран з
  увімкненим прапорцем іде зі змінною частотою (видно в OSD монітора, якщо він
  показує поточну частоту).
- Розробник: `vktest.exe fullscreen` (Esc закриває), у `nt.log` —
  `variable refresh on` / `off`.
- У QEMU (`virtio-gpu`, `bochs`) VRR немає, тож прапорця там не видно, а
  пряме сканування чужих буферів карти не приймають: перевіряється шлях flip
  і композиція.

## Що далі

- Модифікатори (тайлінг) у окремому tranche для повноекранних поверхонь:
  тоді GPU не копіює кадр у лінійний буфер.
- `wp_linux_drm_syncobj_v1` (явна синхронізація) — насамперед для NVIDIA.
- `wp_presentation`, `wp_tearing_control_v1` (VSync off у іграх).
- Vulkan-композиція замість CPU для вікон з GPU-буферами.
- Кілька GPU з моніторами одночасно (зараз монітори другої карти не
  використовуються).
- NVIDIA Kepler (GTX 600/700) на `nouveau` працює без підняття частот:
  повільно (гілка 470 під нове ядро не збирається).
